# 公共报告

**关于 MLA 机制效果的小体量复现探索**

> 对外主文档。配套：[实验方案](experiment_plan.md) · [测试结论](conclusion.md) · [参考结果](reference_results.md) · [操作手册](../guide.md) · 返回 [readme](../readme.md)

单卡 6 GB 显存、64M 级模型、1.5 亿 token 预算。检验 MLA 的两项机制性质：KV cache 的压缩比能否按公式成立，以及吸收式推理相对朴素实现在单请求下是快还是慢。不复现 DeepSeek-V2 的训练配方，困惑度只作同语料同预算下的质量参照。

测量环境：RTX 4050 Laptop，6140.5 MB 显存，BF16，batch 1，时钟未锁定（实测 SM 约 2310 MHz 且随负载浮动）。

## 一、综述

MLA（Multi-head Latent Attention）自 DeepSeek-V2 提出后，被广泛引用为「压缩 KV cache 且不损失性能」的注意力方案，其参数效率与推理加速在多个公开工作中被复述。这些结论各有成立条件，但条件常被省略：压缩比对应的是 MHA 基线而非 GQA 基线；推理加速对应的是批量服务下的 decode 阶段，而非单请求端到端；吸收式实现（absorbed）相对朴素实现（naive）的优势，取决于潜向量维度与上下文长度。

本项目以可完全重现的规模检验其中两条：缓存压缩比，以及吸收相对朴素的时延代价。两条都在模型级与单层基准两处独立测量。

主要发现四项。

1. 缓存压缩按公式成立。每 token 每层 432 个元素，相对 MHA 的 1536 为 3.556×，两种 `head_dim` 下比值一致。
2. 单请求下吸收不省时。`d_c=256` 时 decode 慢 31–35%，prefill 慢 118–135%。
3. 吸收存在盈亏门槛。`d_c` 降至 128 时，32K 上下文下比值首次低于 1。
4. 同预算下 MLA 的验证困惑度比 MHA 高 14.19%，GQA-4 高 1.54%。

本报告不评价 MLA 与 MHA 孰优。项目范围是机制性质的复现与边界测量，不是架构选型建议。

## 二、实验原理

### 2.1 出发点：KV cache 随上下文线性增长

自回归推理的瓶颈之一是 KV cache 的显存占用与访存量。标准多头注意力（MHA）每 token 每层缓存全部键与值，元素数为 `2 · n_h · d_h`，其中 `n_h` 为注意力头数、`d_h` 为单头维度。该量随上下文长度线性增长，在长上下文与大批量下成为主要开销。

降低这一开销有两条思路：减少 KV 的头数（GQA、MQA），或压缩 KV 的维度（MLA）。前者在头维度上做共享，后者改变缓存的内容本身。本节的推导只保留与后续测量直接相关的部分，注意力机制的入门内容不再展开。

### 2.2 MLA 及其工作原理

MLA 为每个头保留独立查询，把键与值联合压缩成一个低秩潜向量，并把位置信息拆分到独立通道。

```text
c_t      = W_DKV h_t              # 潜向量，d_c 维
k_t^C    = W_UK c_t               # 内容键
v_t^C    = W_UV c_t               # 值
k_t^R    = RoPE(W_KR h_t)         # 解耦键，d_rope 维，各头共享

o_t = softmax(q_t^T [k_t^C; k_t^R] / sqrt(d_h + d_rope)) · v_t

cache = { c_t, k_t^R }            # 每个 token 只存这两项
```

推理时缓存元素数为 `d_c + d_rope`，与头数无关。本项目取 `d_c=384`、`d_rope=48`，得 432；MHA 在同样配置下为 1536。压缩比 3.556× 完全由该公式给出，实测只验证实现未偏离公式。

解耦 RoPE 是吸收成立的前提。若对内容键直接施加位置编码，`W_UK` 会与位置相关矩阵耦合，吸收不再成立，且每个前缀 token 的键都需重算。

### 2.3 吸收 MLA 与朴素 MLA

两种执行路径的差别在于展开时机。

朴素实现每一步把全部历史潜向量经 `W_UK` 展成完整键、经 `W_UV` 展成值，再与查询做注意力。展开量与上下文长度成正比，但缓存本身仍是压缩的。

吸收实现把 `W_UK` 并入查询侧投影、把 `W_UV` 并入输出侧投影，使每步只需在 `d_c` 维空间内完成一次乘加，不必显式构造 `n_h · d_h` 维的键值。代价是查询维度被抬高到 `n_h · (d_h + d_rope)`，且该变换只在 decode 阶段有利：prefill 需要先做一次完整展开，展开与注意力的中间量同时驻留。

吸收与 QK-Norm 冲突。若对键施加逐头归一化，归一化的均方根依赖每个键自身，无法并入 `W_UK` 的线性变换，吸收路径即被封死。本项目 MLA 主组按论文结构启用 QK-Norm，因此模型级推理只能走朴素路径；吸收的相对代价在层级基准中单独测量。

## 三、实验方案

### 3.1 模型级对照：单一变量替换与困惑度

四个方案共用同一套训练代码，只替换注意力模块，其余部分完全一致：同一语料（MiniMind 同源中文部分，取 1.5 亿 token）、同一 token 预算（每步 8192 token，共 18310 步）、同一优化器与学习率调度、同一 seed 集合（42、43）、同一分词器（词表 6400）与训练长度（512）。

| 方案 | `n_kv_heads` | 每 token 每层元素 | 参数量 | 本轮 |
| --- | --- | --- | --- | --- |
| MHA | 8 | 1536 | 68,630,784 | 训练 |
| GQA-4 | 4 | 768 | 63,912,192 | 训练 |
| MQA | 1 | 192 | 60,373,248 | 未训练，按公式外推 |
| MLA | 不适用 | 432 | 68,925,696 | 训练，带 QK-Norm |

前三个是同一实现的三个取值，共享程度只由 `n_kv_heads` 决定，`q_norm`、RoPE、SDPA 与掩码代码完全相同；GQA-4 即 `n_kv_heads=4`，KV 头数是 MHA 的一半。MLA 不在这一族内，它不减少 KV 组数，而是压缩 KV 的维度。

共同骨架为 `d_model=768`、8 层、SwiGLU 中间维 2432、词表 6400。

### 3.2 层级基准：吸收与朴素的受控比较

模型级只测到「带 QK-Norm 的 MLA 走朴素路径」，无法回答吸收本身是否更快。为此另搭三层：MHA、朴素 MLA、吸收 MLA，参数名与形状一致，共用同一套 SDPA 与掩码逻辑，固定 `head_dim=64`、`d_c=256`、`d_rope=32`、单层、BF16。

在受控条件下扫描两个维度：`d_c` 取 384、256、192、128，`n_heads` 取 8、16、32，上下文取 2K、16K、32K。每组 30 轮取中位数，prefill 与 decode 分别计时。

### 3.3 测量口径

- 时延只测 batch 1。批量吞吐不在本轮范围内。
- 时钟未锁定，`nvidia-smi -lgc` 返回权限不足，同一检查点两次测量可差 5.8%。因此架构间时延改用 `eval_paired.py` 在同一进程内交替测量，只取配对差值；绝对毫秒数不跨时段比较。
- 32K 上下文需分块 prefill（块长 1024），一次性前向的显存峰值超出 6 GB。
- 每点取 30 轮中位数，不用单次测量。
- 全部汇总表由脚本从原始 jsonl 生成，不手写。

## 四、实验结果

### 4.1 质量：参数量可比的四个方案

GQA-4 的参数量为 63,912,192，比其余三个少 4,718,592，相对 MHA 少 6.88%，原因是 KV 投影的头数减半。因此四者不是同参数比较，而是参数量相差 6.9% 以内的可比比较；GQA-4 的困惑度差与参数节省混在一起，不能单独归因于注意力结构。

| 方案 | 验证 PPL（均值） | 相对 MHA | 测试 PPL（均值） | 墙钟（h） | 吞吐（token/s） | 峰值显存（MB） |
| --- | --- | --- | --- | --- | --- | --- |
| MHA | 9.1402 | — | 8.5476 | 2.434 / 2.437 | 17,129 | 1553 |
| GQA-4 | 9.2807 | +1.54% | 8.5615 | 2.163 / 2.163 | 19,275 | 1467 |
| MLA | 10.4368 | +14.19% | 9.5969 | 2.734 / 2.733 | 15,247 | 1571 |

MLA 的吞吐比 MHA 低 11.0%、比 GQA-4 低 20.9%，多出的两次逐头归一化在前后向各算一遍，是该开销的来源。不启用 QK-Norm 的同规模版本吞吐与 GQA-4 接近（18,992 与 18,294），说明开销来自 QK-Norm 而非低秩 KV。两组 seed 的极差分别为 0.0311（MHA）、0.0931（GQA-4）、0.1592（MLA）。GQA-4 与 MHA 的差值 0.1405 略大于两者极差之和 0.1242，方向在两个 seed 上一致（0.1715 与 0.1095），但幅度与 seed 波动同量级，不作结构差异的判定。

### 4.2 显存与延迟：压缩是否变成速度

缓存压缩在模型级与层级两处独立成立，比值只由公式决定。

| 方案 | 每 token 每层元素 | 字节（BF16） | 相对 MLA |
| --- | --- | --- | --- |
| MHA | 1536 | 3072 | 3.556× |
| GQA-4 | 768 | 1536 | 1.778× |
| MLA | 432 | 864 | 1.000× |

压缩没有直接变成速度。序列长 512、20 个样本、每样本解码 64 步，每格为 seed 42 / 43。

| 方案 | 首 token（ms） | 每 token（ms） | 吞吐（token/s） |
| --- | --- | --- | --- |
| MHA | 14.377 / 14.644 | 9.760 / 10.348 | 854.6 / 800.9 |
| GQA-4 | 15.894 / 15.663 | 10.782 / 10.522 | 777.3 / 802.2 |
| MLA（朴素路径） | 24.754 / 22.043 | 23.865 / 21.449 | 355.2 / 381.6 |

MLA 的每 token 延迟为 MHA 的 2.1–2.4 倍。差距不来自缓存体积：512 的上下文还没有让缓存读取成为瓶颈；差距来自执行路径，QK-Norm 封死吸收后每步都要展开全部历史潜向量，展开量与上下文成正比。归档的 MLA 无 QK-Norm 组在吸收模式下的记录显示每 token 为 9.8–10.4 ms，与 MHA 持平，但该组权重不同，只作机制说明。

### 4.3 吸收的盈亏门槛

层级基准固定 `d_c=256`，比值为 absorbed/naive。

| 上下文 | decode 比值 | prefill 比值 |
| --- | --- | --- |
| 2K | 1.307 | 未测 |
| 16K | 1.340 | 2.179 |
| 32K | 1.351 | 2.353 |

比值随上下文几乎不变，说明差距来自每步的矩阵形状而非缓存读取量，与 4.2 的解释一致。prefill 只测 16K 与 32K：短上下文下分块开销占比过大，数值不具参考性。

`d_c` 扫描（32K）给出盈亏边界。

| `d_c` | 键宽 `d_c+d_rope` | 16K | 32K |
| --- | --- | --- | --- |
| 384 | 416 | 1.602 | 1.686 |
| 256 | 288 | 1.340 | 1.351 |
| 192 | 224 | 1.235 | 1.246 |
| 128 | 160 | 1.158 | **0.965** |

比值随 `d_c` 单调下降，`d_c=128` 在 32K 下首次低于 1。解析判据给出的阈值为 179.2，落在 128 与 192 之间，与实测交叉区间一致。同一配置在 16K 下仍为 1.158，说明翻盘点还依赖上下文长度，判据只给出量级。`d_c=128` 同时把压缩比提高到 6.40×，代价是潜向量表达力下降，该配置的困惑度未测。

## 五、结论与局限性

### 5.1 实验结论

1. **缓存压缩按公式成立。** 模型级 432 对 1536，比值 3.556×；层级在 `head_dim=64` 下得到相同比值，说明压缩量只由 `d_c + d_rope` 决定，与实现无关。
2. **单请求下吸收不省时。** `d_c=256` 时 decode 慢 31–35%，prefill 慢 118–135%，且不随上下文变长而改善。吸收的收益要靠缓存密度换批量吞吐，本轮未测。
3. **吸收存在盈亏门槛。** `d_c` 降至 128 时 32K 下比值 0.965，首次转正；判据阈值 179.2 与实测交叉区间吻合。翻盘点同时受上下文长度影响。
4. **质量代价可量化。** 同语料同预算下 MLA 的验证困惑度比 MHA 高 14.19%，训练墙钟多 12.3%，吞吐低 11.0%；GQA-4 的差值方向在两个 seed 上一致，但幅度与 seed 波动同量级。
5. **主组 MLA 的时延劣势来自 QK-Norm 而非低秩结构。** 启用 QK-Norm 是为结构对齐，其代价是吸收路径封闭与两次逐头归一化。

### 5.2 过程问题与修正

测量过程中出现的与公开结论不符之处，以及实现层面的修正，一并记录如下。

| 项 | 现象 | 原因 | 处理 |
| --- | --- | --- | --- |
| 与「吸收加速推理」的公开结论不符 | 单请求下吸收慢 31–35% | 公开数字对应批量服务的 decode，且把 prefill 与 decode 分账；本项目为单请求端到端 | 两者不矛盾，报告中标明条件 |
| 分块 prefill 与一次性前向结果不一致 | 输出差异远超浮点误差 | 掩码写成 `is_causal=(past is None and t > 1)`，带 `past` 时掩码被关闭，模型看到未来 token | 改为显式 `tril(diagonal=total−t)`，自检相对误差回到 1e-06 量级 |
| `d_c=171` @32K | 吸收 150.78 ms，比值 38.08 | 键宽 203 不是 8 的倍数，SDPA 走慢路径 | 作废，出图时剔除 |
| `n_heads=32` @32K | 吸收 198.79 ms | 键宽过大导致内核退化 | 作废 |
| 早期得出「吸收更快」 | 与后续测量相反 | 单次测量，抖动被当成差异 | 改为每点 30 轮取中位数，结论修正为吸收更慢 |
| 推导「`n_heads` 超过 10.1 时吸收翻盘」 | 与实测矛盾 | 判据推导中 `d_c` 与 `d_rope` 的处理写错 | 撤回，改用 4.3 的判据式 |
| 模型级缓存基准三组被压平 | 三组 decode 差异消失 | 逐步计时把每步同步与采样开销计入 | 改为整段计时后除步数 |
| 缓存按元素计的字节数偏高 | MHA 平均每元素 3 字节，理论值应为 2 | RoPE 表在 autocast 下未降到 BF16，仍以 FP32 参与，缓存读取按混合精度计 | 把 RoPE 表降到 BF16 后重测（fixed），MHA 回到 2 字节；3.556× 只在 fixed 下成立，图内 raw 与 fixed 两条线并列 |

### 5.3 局限性与其他考量

1. 时延固定 batch 1。吸收的真实价值在批量服务下的缓存密度与吞吐，本轮未测，因此不能据此判定吸收无价值。
2. 上下文上限 32K。更长需要更多显存或更激进的分块，未验证。
3. 规模只到 64M 级、1.5 亿 token。困惑度差异在该规模下稳定，但不能外推到更大模型。
4. 查询侧缺少论文的低秩分支（`W^DQ` 后接 `W^UQ`），本项目查询侧为满秩投影，参数量与原始结构不完全对齐。该缺失不作用于 KV 侧，不影响吸收路径的时延测量。
5. 单机单卡，seed 只有两个，统计功效有限；两配置差值小于 seed 极差时一律记为未观测到显著差异。
6. 时钟未锁定，绝对毫秒数跨时段不可比，所有架构间比较只用配对差值。

后续可补的工作有三项：批量大于 1 的吞吐测量，把吸收的收益放回它本来的成立条件；超过 32K 的长上下文与分块策略；在锁频环境下重测时延以缩小置信区间。

复现入口：`python run_all.py --dry-run` 打印全部命令，`python run_all.py` 依次执行检查、切分、训练、评测、层级基准、汇总与出图。环境、目录约定与故障排查见仓库根目录的 `readme.md` 与 `guide.md`，逐条数字与推导见 [reference_results.md](reference_results.md)，测试结论明细见 [conclusion.md](conclusion.md)，实验设计见 [experiment_plan.md](experiment_plan.md)。
