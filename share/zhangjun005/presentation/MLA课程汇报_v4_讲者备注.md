# 01_多头潜注意力（MLA）

今天介绍多头潜注意力 MLA。它要解决的是大语言模型推理时历史键值缓存越来越大的问题。汇报先从逐步生成和自注意力讲起，再说明 MLA 如何压缩缓存、保留位置信息并改变计算顺序，最后看简化实验中的缓存、质量和运行时间。

这里介绍注意力结构如何支持推理。原论文同时提出 MLA 和稀疏专家模型 DeepSeekMoE；今天主要解释 MLA，涉及完整模型的服务结果时再把其他系统条件补回来。顺序是先说明缓存为什么成为问题，再推导方法，最后通过我们的实验与论文两种尺度的证据理解它。

---

# 02_大语言模型推理中的长上下文问题

语言模型不是一次输出整段文本，而是根据已有文本逐个生成 token。每一步都要把刚生成的内容加入上下文，下一步继续使用。上下文越长，模型要保留的历史状态越多；并发请求增加时，这份状态会按请求数重复保存。MLA 关注其中的 KV cache。

例如让模型总结一篇长文，输入前缀本身已经很长，回答过程还会继续增加历史。如果服务器同时处理很多人的请求，每人都要保存自己的状态。这使推理显存不仅取决于模型权重，还取决于上下文长度和同时服务的人数。要看清哪些状态可以压缩，需要先回顾注意力的查询、键和值。

---

# 03_自注意力如何使用历史信息

一个注意力头用当前查询 Q 表示“我现在要找什么”，用历史键 K 表示每个历史 token 的匹配特征，用历史值 V 表示可以取回的信息。Q 和每个 K 做点积，再经过 softmax 得到权重，最后按权重加和 V。多头只是并行做多组这样的投影。为了让数值更具体，页上的 0.2、0.3、0.5 是示意权重。

这些投影都来自隐状态，不是人为给词语指定的标签。注意力头可以学习不同的匹配方式和信息表示。新 token 到来时查询会变，但同一层已经处理过的历史键和值可以复用。正是这部分可复用状态组成我们下一页要讨论的缓存；缓存本身并不保存所有历史查询。

---

# 04_KV cache 的作用与显存开销

Prefill 处理输入前缀，可以并行算出历史 K/V；decode 每次只生成一个新 token，但会重复读取历史 K/V。保存它们可以避免重复投影。公式把请求数、长度、层数、KV 头数和头宽都列出来。示例的 4 GiB 是只算 KV 的理论估算，不能当整张显卡的峰值显存。

公式中的每元素字节数把结构和数值精度分开了。固定结构时，长度或并发翻倍会让缓存近似翻倍；固定长度时，共享更多 KV 头或降低存储精度也能减小缓存。这里八千指八千一百九十二，按二进制容量计算得到四 GiB。MLA 主要改变缓存向量的表示，和量化可以组合使用。

---

# 05_MHA、GQA 与 MQA

MHA、GQA 和 MQA 都直接共享完整的 KV 头。固定八个查询头时，KV 头从八组减到四组或一组，缓存随之减少，但多个查询头看到的是同一组完整 K/V。MLA 之后会改成共享产生 K/V 的潜向量，概念上不是简单地再减少 KV 头。

页上图示固定八个查询头，每个头仍然可以有自己的查询投影。GQA 的四个 KV 头由每两个查询头共用，MQA 只剩一个 KV 头。它们直接改变完整键和值的共享关系。MLA 则允许各头有不同的上投影，让共享来源和各头表达同时存在，这就引出了低秩联合表示。

---

# 06_MLA 的联合低秩表示

输入隐状态先经过下投影得到较短的潜向量 c。每个注意力头有自己的上投影，因此能从同一个 c 产生不同的内容键和值。缓存里保存的是每个 token、每层的一份 c，而不是每个头各存一份。低秩表示是模型训练学到的结构约束，不保证把任意现有 MHA 无损转换。

这里的低秩不是把已有缓存简单截断。下投影和上投影在训练时共同学习，让后续任务需要的信息尽量进入较小的表示。多个头来自共同的 c，但乘的是不同矩阵，因此不能把它理解成所有头的键和值相同。下一步要解决的是保存得少以后，怎样在计算时也利用这种结构。

---

# 07_从压缩缓存到潜空间计算

只把历史 K/V 换成 c，存储确实变少，但如果每一步都把整段历史 c 重新展开成多头 K/V，计算和中间数据仍然存在。因此 MLA 还需要改变计算路径。接下来先忽略位置编码，分别看键投影和值投影怎样利用线性关系直接在潜空间工作。

朴素路径很容易实现，也有教学价值：从 c 重新产生键和值后，可以继续调用标准注意力接口。但 decode 每走一步都会再次访问整段历史，重复恢复的代价随历史长度扩大。矩阵吸收不是额外压缩一次，而是利用同一组权重的线性关系重排运算，减少这部分反复展开。

---

# 08_一个潜向量怎样生成较宽的键和值

这里先把上投影变成一个可以手算的小例子。三个历史 token 的潜向量分别是一、二，二、一，以及一、一。我们暂时令键和值使用同一条规则：保留两个输入数，再补上它们的和。所以第一行的一、二变成一、二、三；第二行变成二、一、三；第三行变成一、一、二。

图中每个小格就是向量里的一个数，从两格到三格就是这次示意的展开。真实模型的键投影和值投影是分别学习的矩阵，这里用相同规则只是为了便于比较计算顺序。真实潜宽也可以大于单个头的宽度，压缩主要针对所有头的联合表示，不能从这个两格到三格的例子直接套用实际维度比例。

如果采用恢复路径，每一个历史 token 都要通过这条规则得到较宽的键和值。接下来的两页保持规则不变，分别检查能否跳过历史键和历史值的生成，同时得到相同计算结果。

---

# 09_键侧：改算查询，就能得到相同分数

先看键侧。当前查询是一、一、一。上半部分沿用刚才的三组历史键，分别与这个查询点积。第一行是一乘一，加一乘二，再加一乘三，得到六。第二行也是六，第三行是一加一加二，得到四。因此先展开历史键的路径得到六、六、四。

为什么下面可以省去三格的历史键？把任意一行的潜向量写成 x、y，展开后的键就是 x、y、x加y。当前查询的三个系数都是一，所以点积是在算 x加y再加x加y，也就是二倍x加二倍y。我们可以先把这三个查询系数合成两个系数，也就是把当前查询变成二、二。

现在用二、二直接与缓存中的两格向量匹配。第一行是二乘一加二乘二，得到六；第二行是二乘二加二乘一，还是六；第三行得到四。两条路径读取的是同一份历史潜向量，分数完全相同，但下半部分没有产生上半部分三列历史键。变换只发生在当前查询上，然后重复用它匹配所有历史。

一般线性投影也有这样的系数重组，对应键上投影矩阵转置作用于查询。这里只看内容分数，还没有加入位置项。保持相同缩放和 softmax 后，同样的分数会得到同样的权重。省掉历史键展开也不等于不用读取历史，三个潜向量依然都要参与点积。

---

# 10_值侧：先加权潜向量，再展开一次

键侧解决的是得到权重以前怎样匹配；值侧解决的是得到权重以后怎样取回信息。这里为了方便手算，单独指定零点二、零点三和零点五三个权重，它们不是上一页六、六、四经过 softmax 的结果。

上半部分先使用三格的历史值，再按权重相加。第一个坐标是零点二乘一，加零点三乘二，再加零点五乘一，得到一点三。第二个坐标同理得到一点二。第三个坐标得到二点五，所以输出是一点三、一点二、二点五。

下半部分直接对两格的潜向量加权。第一个坐标还是一点三，第二个坐标还是一点二，这时只有一个聚合后的两格向量。再对这个向量使用同一条上投影规则，补出两者之和二点五，就得到与上面完全相同的三格输出。

关键在于，线性上投影可以放到加权求和之后。上面需要三份历史值展开，下面只把一个聚合结果展开一次。历史越长，这两种安排涉及的中间向量数量就越不同。真实多头计算中，每个头仍要用自己的权重求聚合结果，再做自己的值和输出投影；softmax 没有被省去。

---

# 11_多个头怎样共用历史潜向量

把刚才三个 token 的例子推广到任意历史长度，就能看到多头情况下省掉了什么。左侧是一份历史潜向量缓存，每个 token 占一行。右侧两个头各自把当前查询变换到潜空间，读取这同一份缓存计算分数，再用各自的注意力权重聚合历史潜向量。每个头只需要把自己的聚合结果做值和输出投影。

共享缓存不意味着两个头相同。各头查询的变换矩阵可以不同，得到的分数、权重和聚合结果也不同。图中从缓存连到右侧运算，表示各头读取共享历史；当前查询来自当前隐状态，并不是由历史缓存生成。

直接恢复时，需要产生按头数、历史长度和头宽组织的整段历史键和值。潜空间路径避开的是这一批多头历史中间张量，仍会读取全部历史 c，也仍会产生各头的当前查询和聚合结果。因此数学重排可以减少历史展开，但实际点积宽度、临时张量和硬件内核仍会影响时延。到这里暂时只处理内容，下一步把语言顺序所需的位置信息加回来。

---

# 12_位置编码对矩阵吸收的影响

内容之外还要表示顺序。RoPE 通过按位置旋转查询和键，让相同词在不同位置产生不同的相对关系。如果把旋转后的完整键写成矩阵式，历史位置 j 对应的旋转矩阵位于投影中间，它随 j 变化，因此不能直接用一个固定变换处理所有历史键。问题是固定矩阵吸收受到影响，不是说 RoPE 不能缓存。

这里的旋转矩阵是随位置变化的。对每个历史 j 使用的相对旋转不同，因而不能像上一页那样把它们统一并入一次当前查询变换。我们不是要取消位置信息，而是要让需要位置旋转的部分足够小，同时让需要吸收的内容分支继续保持简单线性关系。

---

# 13_解耦旋转位置编码

MLA 把内容和位置拆成两条分支。内容分支保持线性，位置分支单独施加 RoPE；位置查询按头区分，位置键跨头共享。两部分分数相加后再缩放和 softmax。缓存保存共享内容潜向量 c 和位置键 kR。位置宽度 dR 也进入原注意力的缩放定义。

拼接向量的点积等于两部分点积之和，所以这样拆分可以自然接回注意力。吸收之后内容查询变成潜宽，但缩放仍沿用原始内容宽度加位置宽度的平方根，不能随意改成吸收后的宽度。模型还可以对查询做低秩投影，论文用它节省训练激活，不过它不进入历史 KV 缓存。

---

# 14_MLA 的推理流程

完整 decode 时，当前输入先产生新的潜向量和位置键并追加到缓存。当前内容查询和位置查询分别读取历史 c 与位置键，得到内容分数和位置分数。softmax 后，权重先聚合历史潜向量，再执行值投影和输出投影，送到下一层。关键是历史没有整体恢复成多头 K/V。

现在可以把三个机制串起来：新 token 只追加一份共享内容潜向量和一份位置键，各头的查询依然不同。内容打分在潜空间进行，位置分数单独计算，两者相加后得到权重，再在潜空间聚合。这个流程说明理论上的实现目标，接下来查看我们的实验具体保留了什么，又作了哪些简化。

# 15_我们的实验怎样组织

下面把原理对应到我们的实验实现。上半部分从同一份 token 数据出发，分别训练 MHA、四个键值头的 GQA，以及简化 MLA 三个语言模型。它们各自学习自己的参数，训练后分别评估验证困惑度 PPL，并检查每层返回的缓存。这个比较回答当前训练预算下的预测质量和缓存占用。

下半部分另建独立注意力层，固定层结构参数和输入形状，对恢复历史 K/V 与吸收两种路径分别计时。它直接使用随机隐向量，不需要先训练一个语言模型。这里需要区分正确性检查和性能测量：前者复制同一份权重，用同一小输入检查结果；实际计时则分别初始化实例，并使用各自生成的随机输入，没有逐步配对同一份数值数据。后面会展开这个程序过程。

模型级比较和层级比较对应不同问题，不能把某个层的时延比直接视为训练后模型的服务加速比。此次汇报沿用留存的训练和计时数据，所做的是实现核对与离线统计。先按实际执行顺序看模型怎样搭建，再看训练样本、缓存更新和测量方法。

# 16_我们的语言模型怎样搭起来

模型输入首先是 token 编号，不是人工写好的特征。词嵌入层把每个编号查成一个隐向量，然后依次通过八个 Transformer 块。最后经过末端归一化和词表投影，得到每个位置对词表中所有候选 token 的预测分数；训练时把这些分数交给交叉熵，生成时则据此选择下一个 token。

下面展开一个块。第一段先归一化输入，再送入注意力模块，把注意力输出加回这段的原输入，这是第一次残差连接。第二段对相加后的向量再归一化，送入 SwiGLU 前馈网络，再加回这段输入，形成第二次残差连接。这样的块重复八次，每一层都有自己的注意力参数和缓存。

三种模型替换的是图中注意力的位置，外面的词嵌入、前馈骨架和预测任务保持相同。简化 MLA 保留联合压缩和解耦位置分支，但查询直接从隐向量投影，省略论文的查询低秩分支。不同注意力结构仍会带来参数量差异，因此这个实验并不是严格等参数对照。具体维度放到附录，先看这些可训练矩阵是怎样学习的。

# 17_一次训练步骤做了什么

训练样本来自连续的 token 流。图中的文字只作示意：输入是“我、喜欢、机器”，目标就向后错一位，变成“喜欢、机器、学习”。这样“我”的位置学习预测“喜欢”，“喜欢”的位置学习预测“机器”。因果掩码保证每个位置只能使用当前及之前的信息，不能偷看目标所在的未来位置。

程序实际连续取五百一十三个 token，前五百一十二个作为输入，后五百一十二个作为目标。一次模型前向给出各位置的词表分数，交叉熵比较真实目标与预测分布，反向传播把损失的影响传回各个参数，随后通过 AdamW 更新参数。实际还包含梯度累积和裁剪，图中展示的是数据与参数更新的主要关系。

MLA 的下投影、各头的键和值上投影，都在这个预测任务中通过梯度学习。因此共享潜向量不是训练后手工从 MHA 缓存里删掉一些坐标，而是从训练开始就由这种结构承担信息表示。训练完成后，用未参与参数更新的验证文本检查预测质量；接下来先看推理时保留了哪些历史状态。

# 18_推理时，缓存怎样建立和更新

推理有两个阶段。左边的 prefill 一次输入 a、b、c 三个 token，每一层为它们产生内容潜向量和位置键。程序把这两类张量放在该层的 past 中返回，下一次调用可以继续使用。图中的 r 是前面的位置键，只是为了缩短标记；加号表示一起保存两类状态，不是把两个向量按元素相加。

prefill 的最后位置给出下一 token 的预测。如果选出 d，再把这个新 token 作为 decode 输入。当前层算出它的新潜向量和位置键，并追加到原来的历史末尾。于是内容缓存从三行变成四行，每行三百八十四维；共享位置键也从三行变成四行，每行四十八维。批量一时，代码中的形状分别是一个批量、历史长度、三百八十四，以及一个批量、一个共享头、历史长度、四十八。

注意力随后读取第一到第四项，完成当前 token 的计算，再把更新后的 past 交给下一步。每层都有这样一份状态，重复生成时历史行数持续增长。我们的主模型虽然持久缓存只保存 c 与位置键，但计算中采用临时恢复 K/V 的路径，和前面理论上的直接潜空间计算有区别。下一页的归一化位置说明这个选择为什么影响简单矩阵吸收。

---

# 19_归一化位置与矩阵吸收

RMSNorm 根据向量幅度对它归一化，因此整个映射不是固定的线性矩阵。官方参考代码先在低维潜向量上做 RMSNorm，再上投影。我们可以把归一化后的向量当作新的缓存 c，后面的键上投影仍然线性，前面推导的吸收继续成立。这一比较针对的是官方参考实现，论文主公式省略了这些细节。

我们的主模型先上投影得到每个头的内容键，再分别归一化。分母取决于每个历史键自身，也随头变化，不能直接用一个固定矩阵并入当前查询。所以主组采用恢复路径，它的 PPL 数据也不能直接代表独立层吸收实现的语言质量。限制来自归一化放置位置，而不是 MLA 和 RMSNorm 固有冲突。把这个实现选择讲清楚后，才适合讨论独立层对线性重排的测量。

# 20_两种注意力计算怎样比较

层级测量直接把随机隐向量送进注意力层，跳过词嵌入、前馈和语言模型训练。第一步是小输入的正确性检查：先创建恢复实例，再把参数复制给吸收实例，让两者处理同一个 FP32 小输入，比较最大相对输出误差。程序还检查分块 prefill 与一次性 prefill 的输出及缓存，用来发现历史位置和因果掩码的问题。

第二步另建 BF16 性能计时实例。这一步的恢复和吸收实例分别随机初始化，输入也分别随机生成；代码没有延续小输入检查中那份共享权重，也没有给两者保存完全相同的输入数值。因此真正控制的是层结构、输入形状、精度和上下文协议，这是一项实现性能观察，不能说成同权重同输入逐步配对的受控测量。

第三步分块输入隐向量，分别填好两种路径的缓存，推进到同样的历史长度。第四步每次只输入一个新隐向量，用两个 CUDA 事件包围注意力前向，前向中也包含缓存追加；同步后读取毫秒数。随机输入在计时开始前生成。每轮记录二十四步，代码取排序后的第十三个作为该轮摘要；每种实现三轮，再分别取轮摘要中位数，最后算吸收耗时除以恢复耗时。

图中是操作顺序，完整配置在附录。历史测量来自约六 GB 的 RTX 4050 Laptop，当前四零六零八 GB 没有重测。小输入检查不能替代每个长序列 BF16 点的数值验证，随机层计时也不评价语言理解能力。

# 21_图里的三个指标怎样得到

前面三个指标在程序里有不同的来源。模型质量先把验证文本送入模型，计算真实后续 token 的平均交叉熵，再取指数得到 PPL。越低表示模型给真实后续文本分配的概率越高；它不是分类准确率。本次图中的两个点来自两个随机种子的留存评估记录。

缓存容量来自 prefill 返回的 past。程序逐层检查其中的缓存张量，把每个张量的元素个数乘以每元素字节数，再把它们相加。比较图统一使用 BF16，因此每个元素两字节。这个数只包含持久缓存，不包含权重、临时展开的 K/V 和算子工作空间，不能直接当作整张显卡的峰值显存。

计算时间来自独立层的 CUDA 事件记录。我们沿用程序每轮二十四步的摘要，对三轮摘要分别取中位数，再计算吸收除以恢复的耗时比。大于一表示吸收更慢，小于一才表示吸收更快。PPL、缓存字节和时延比对应不同对象，不能互相替代。此次只复算和整理已有数据，没有重跑训练或 GPU 性能测量。明确了这些来源后，下一页再读数值结果。

# 22_缓存占用与模型质量

先看模型级结果。左边统一按 BF16、批量一、五百一十二个 token、八层来比较缓存张量。MHA 十二 MiB，GQA-4 六 MiB，MLA 三点三七五 MiB。MLA 每 token 每层只存三百八十四维 c 加四十八维位置键，合计四百三十二个元素，MHA 则是一千五百三十六个，所以减少百分之七十一点八七五，压缩约三点五五六倍。这里只算缓存张量，不包含权重和工作空间，不能叫整模型显存减少同样比例。

右边展示两个种子的验证 PPL，均值分别约九点一四零、九点二八一、十点四三七。PPL 越低越好，当前简化 MLA 比 MHA 高约百分之十四点一九。纵轴只展示八点五到十一，种子点在横向略微错开以便观察。两个种子只能描述这份配置，不能得出普遍质量结论，也不能把 PPL 上升说成准确率下降同样百分比。接下来只改变同权重层的计算路径，看吸收的时间表现。

# 23_矩阵吸收的运行时间

纵轴是吸收路径耗时除以恢复 K/V 路径耗时，因此一是持平，高于一表示吸收更慢。横轴是四个潜宽类别，按类别等距排布，连线用于方便阅读，不能当成连续拟合。蓝线是一万六千上下文，绿线是三万二千。潜宽较大时，两条曲线都明显高于一；例如三百八十四维时约一点六零二和一点六八六。

三万二千、潜宽一百二十八的比值约零点九六五，观察上略快，但只有三轮、不同潜宽又来自不同会话，实际计时还分别初始化实例和随机输入，不能宣布找到了稳定的加速阈值。这个较小潜宽也没有对应的语言质量评测，所以没有证据说它同时保持质量。这些随机输入层计时更不能证明模型理解三万二千长文。要解释为什么线性重排没有稳定加速，需要回到实际张量形状。

# 24_矩阵吸收为什么没有稳定加速

矩阵恒等式保证的是相同计算定义，不保证硬件执行更快。恢复路径的内容键是六十四维，加位置三十二维，打分内维共九十六。吸收以后内容打分进入潜宽，内维变成潜宽加三十二；潜宽一百二十八时是一百六十，三百八十四时是四百一十六。因此虽然省去了恢复历史 K/V 的上投影，点积和潜空间聚合也可能变宽。

当前独立层 吸收实现还把共享 c 展开到头维，再和位置键拼接，拼接会物化多头 K 中间张量。值侧先聚合潜向量，再执行值上投影和输出投影，尚未合成融合部署内核。持久缓存变小和临时工作空间变小是不同问题。这些是从代码观察到的可能开销来源，尚未做算子级因果消融。本页分析的是实际选用的独立层路径，优化部署内核的计算和访存安排还会不同。下面把尺度扩大，看原论文怎样提供质量证据。

# 25_原论文中的质量对照实验

原论文附录 D.2 的表九直接比较注意力机制，适合补充课程小实验。小规模 MoE 总参数约一百六十亿，训练一点三三万亿 token；大规模约二千五百亿，训练四千二百亿 token。每个规模组除了注意力机制之外使用同一骨架，但总参数和激活参数并未严格相同，因此仍需要保留比较条件。MoE 指稀疏专家模型，每个 token 只激活其中部分专家。

表中四个任务分数都越高越好，BBH 主要测试复杂推理，MMLU 是多学科知识，C-Eval 和 CMMLU 是中文综合评测。大规模组 MLA 的四项都高于 MHA，例如 MMLU 从五十七点五到五十九点零。小规模组有三项提升，但 C-Eval 从五十一点六到五十点九，略有下降。BBH 使用三样例提示，其余五样例。这说明论文配方下可以兼顾缓存压缩和整体质量，但不能把结论说成每项必升，也不能直接与我们实验的 PPL 相减。接下来再看真实服务部署。

# 26_DeepSeek-V2 的实际部署效果

DeepSeek-V2 摘要报告，相对 DeepSeek 六十七 B，KV cache 减少百分之九十三点三，最大生成吞吐为五点七六倍。这里的比较对象是两个完整模型和服务系统。DeepSeek-V2 总参数二千三百六十亿，每个 token 激活二百一十亿，采用 MoE；基线是先前的稠密模型，因此不能把全部差异归为单独更换 MLA。

论文第三点二点三节说明，部署把权重转换为 FP8，KV 元素平均量化为六 bit，更小的缓存允许更大服务批量。作者按已部署 DeepSeek 六十七 B 服务的输入和生成长度分布评测。单节点八张 H800 的生成吞吐超过每秒五万个 token，输入吞吐超过每秒十万个 token。该段没有给固定输入输出长度和确切 batch，我们也不补造。五点七六倍是最大服务总吞吐，不是一个用户的逐 token 延迟快同样倍数。下一页从缓存与并发的关系解释它的应用意义。

# 27_缓存压缩如何改善服务吞吐

服务吞吐衡量单位时间所有请求合计生成多少 token，单请求时延衡量某个请求等待多久。每个请求缓存变小，在权重和工作空间占用之后，同样显存通常可以容纳更多请求，为更大批量创造条件。更大的批量可能提高硬件利用率和整体吞吐，但不能据此保证每个人的响应延迟都会变短。缓存也只是显存的一部分，吞吐不会简单按缓存压缩倍数线性增长。

论文表九另外给出了同组内的缓存元素数。小规模组从每 token 全层约十一万零六百个元素降到一万五千六百，约为原来的百分之十四；大规模从八十六万零二百降到三万四千六百，约为原来的百分之四。这些是元素数量比较，比较模型又不同于上一页 DeepSeek-V2 对六十七 B 的百分之九十三点三，不能相互替换，也没有在这里计入六 bit 量化。我们批量一批量一的层时延与多卡服务吞吐分别支持不同结论，我们最终要把方法机制和证据范围一起带走。

# 28_总结

MLA 的方法可以沿一条技术主线理解。先用联合低秩表示让各头内容键和值共享一个较小潜向量，减少持久缓存；再把旋转位置编码放入独立分支，让内容上投影保持线性；最后通过矩阵吸收改变键匹配和值聚合的顺序，直接使用潜缓存。

我们的实验给出缓存压缩约三点五五六倍的具体例子，也显示当前简化结构的 PPL 和独立层实现仍有质量与计算开销。原论文则在更大训练和部署条件下给出另一层证据：同组质量对照以及相对 DeepSeek 六十七 B 的五点七六倍最大生成吞吐。解释这组工业效果时，要同时保留模型结构、量化、硬件和服务批量条件。这样既能介绍 MLA 的技术价值，也能说明为什么我们的简化实验没有复现同样的速度倍数。缓存收益、模型质量与服务速度，各自需要对应的比较与测量。
